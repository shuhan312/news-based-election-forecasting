# Reproducibility guide

How to reproduce every figure, table and headline number in the final report
from this repository's `main` branch. This file is operational; the
methodology is in the report, and the full report-section → artefact → code
trace is in [`REPO_MAP.md`](REPO_MAP.md).

## 1. What "reproduce" means for each layer

The pipeline has a single reproduction boundary:

- **Not re-run.** The two stages that consumed the outside world — news
  collection (live APIs and archives) and LLM extraction (the Claude batch
  API; costly and not deterministic) — are not repeated. Their frozen
  outputs are the reproduction boundary: every keep/drop decision, batch
  id, prompt fingerprint and SHA-256 is committed, so those outputs are
  verified and audited rather than regenerated. Raw article text and raw
  model responses stay off Git (copyright and the large-file rule);
  per-directory READMEs state what is local/OneDrive.
- **Reproducible from the boundary.** Everything downstream — the election
  releases, the Stage 1 baseline, the feature tables, the Stage 2 fits and
  scoring, and the report tables and figures — deterministically
  reproduces the reported numerical results and artefacts from committed
  (or restored) frozen inputs using the commands below. Where byte-level
  identity is additionally pinned by a test, the step says so.

No API key is needed for any reproduction step below. Keys (SerpAPI,
Anthropic) were only needed to create the frozen snapshots.

## 2. Environment

Python 3.14 (developed on 3.14.6; the report-side CI also runs 3.14).

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt                                  # main pipeline
pip install -r surrey-election-extractor/requirements.txt        # Layer 1A subproject
pip install -r surrey-election-no-news-baseline/requirements.txt # Stage 1 subproject
```

## 3. Data sources and access

| Data | Source | Access |
| --- | --- | --- |
| Election results 2013–2026 | Surrey County Council official result pages; Internet Archive captures where the live page is blocked; Wikipedia for borough/district context and the 2013 turnout gap | committed as `data/elections/*.csv` and the extractor's `config/` evidence; every value carries its source URL (`surrey-election-extractor/README.md`) |
| News articles | SerpAPI-indexed searches, publisher search (SurreyLive, BBC Surrey), the Guardian Open Platform, web archives | frozen snapshot: the query plan, append-only search log and all eligibility decisions are committed in `news_collection/`; raw text is local (`data/raw/news/`, git-ignored) |
| LLM labels | Claude batch API (Sonnet 5 for issue, Haiku 4.5 for stance/framing) | frozen snapshot: agreement scorecards, batch digests and SHA-256 manifests committed in `llm_context/`; raw responses local/OneDrive |
| Large binaries (workbooks, model bundle, blinded prediction CSVs) | generated by this repository | regenerated by the commands below, or fetched from the OneDrive links in the owning directory's README; their SHA-256 hashes are committed beside them |

## 4. Rebuild order (fresh clone)

Run everything from the repository root with the `.venv` active. Steps 1,
2, 4, 5 and 6 need only committed files. Step 3's optional rebuild (and any
test that reports itself as skipped) additionally needs the git-ignored
frozen LLM tranches restored from the locations named in
`llm_context/README.md`; because the feature tables themselves are
committed, you can also skip Step 3 and proceed with the frozen CSVs.

**Step 1 — Layer 1A: election releases (offline, deterministic).**

```bash
PYTHONPATH=surrey-election-extractor .venv/bin/python surrey-election-extractor/scripts/generate_master_election_database.py
PYTHONPATH=surrey-election-extractor .venv/bin/python surrey-election-extractor/scripts/generate_final_position_qa.py
PYTHONPATH=surrey-election-extractor .venv/bin/python surrey-election-extractor/scripts/generate_final_election_data_release_audit.py
PYTHONPATH=surrey-election-extractor .venv/bin/python surrey-election-extractor/scripts/generate_no_news_electoral_baseline.py
PYTHONPATH=surrey-election-extractor .venv/bin/python surrey-election-extractor/scripts/generate_no_news_candidate_contests.py
PYTHONPATH=surrey-election-extractor .venv/bin/python surrey-election-extractor/scripts/generate_no_news_party_contests.py
```

**Step 2 — Stage 1: the history-only baseline.**

```bash
PYTHONPATH=surrey-election-no-news-baseline .venv/bin/python -m no_news_baseline.cli train
```

Acceptance: the run logs out-of-fold MAE 9.85 and holdout MAE 4.53, and
writes `surrey-election-no-news-baseline/outputs/model_bundle_v1/` with its
SHA-256 manifest.

**Step 3 — Layer 4: the news feature tables (optional).** The committed
`news_features/news_feature_table_v1/v2/v3exp/v3party.csv` are the frozen
releases. With the frozen LLM tranches restored, each rebuilds
byte-identically — a claim pinned by `tests/test_feature_table_rebuild.py`
rather than asserted:

```bash
python3 -m src.news_features.build_feature_table
python3 -m src.news_features.build_feature_table_v2
python3 -m src.news_features.build_feature_table_v3exp
python3 -m src.news_features.build_feature_table_v3party
```

**Step 4 — Stage 2: freeze, unblind, diagnose (deterministic).**

```bash
PYTHONPATH=src .venv/bin/python -m news_modelling.run_blinded_2026_predictions
PYTHONPATH=src .venv/bin/python -m news_modelling.run_blinded_2026_predictions_v2
PYTHONPATH=src .venv/bin/python -m news_modelling.unblind_2026
```

Every post-unblinding diagnostic regenerates its `news_features/<name>_v1/`
evidence directory via its module in `src/news_modelling/` (one module per
analysis; see that README's file guide).

**Step 5 — Layer 7: the report tables and figures.**

```bash
PYTHONPATH=src .venv/bin/python -m news_modelling.build_report_tables
PYTHONPATH=src .venv/bin/python -m news_modelling.report_appendix_tables
PYTHONPATH=src .venv/bin/python -m news_modelling.make_report_figures
```

Build-time assertions fail if any number drifts from its frozen source;
`outputs/report_tables_v1/manifest.json` pins the SHA-256 of every input.

**Step 6 — the report PDF.**

```bash
make -C report
```

`report/report.tex` reads only the committed packs in
`outputs/report_tables_v1/` and `outputs/report_figures_v1/`.

## 8. Verification without rebuilding anything

```bash
python3 -m audit_leakage_provenance      # five offline checks: query lineage, chronology,
                                         # outcome isolation, the prediction freeze, area selection
.venv/bin/python -m pytest tests -q                                                # root news side
( cd surrey-election-no-news-baseline && PYTHONPATH=. ../.venv/bin/python -m pytest tests -q )  # Stage 1
( cd surrey-election-extractor && ../.venv/bin/python -m pytest tests -q )          # extractor
.venv/bin/python -m pytest demo/test_viva_pack.py -q                               # viva pack
```

Tests that need git-ignored local inputs (the frozen LLM tranches, the
collection runner state) skip themselves on a fresh clone; each skip message
names the file to restore or the builder that recreates it.

## 9. Outputs

Rebuilt products land where the committed versions live: extractor releases
under `surrey-election-extractor/outputs/`, the Stage 1 bundle under
`surrey-election-no-news-baseline/outputs/model_bundle_v1/`, feature tables
and experiment evidence under `news_features/`, and the report packs under
`outputs/report_tables_v1/` and `outputs/report_figures_v1/`. Only the report
packs and the small evidence files are committed; everything else is
regenerable output and stays out of Git.
