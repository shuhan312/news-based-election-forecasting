# Reproducibility guide

How to reproduce every figure, table and headline number in the final report
from this repository's `main` branch. This file is operational; the
methodology is in the report, and the full report-section → artefact → code
trace is in [`REPO_MAP.md`](REPO_MAP.md).

## 1. What "reproduce" means for each layer

The pipeline has a single reproduction boundary:

- **Not re-run.** The two stages that consumed the outside world — news
  collection (live APIs and archives) and LLM extraction (the Claude batch
  API; costly and not deterministic) — are not repeated. Their frozen
  outputs are the reproduction boundary: every keep/drop decision, batch
  id, prompt fingerprint and SHA-256 is committed, so those outputs are
  verified and audited rather than regenerated. Raw article text and raw
  model responses stay off Git (copyright and the large-file rule);
  per-directory READMEs state what is local/OneDrive.
- **Reproducible from the boundary.** Everything downstream — the election
  releases, the Stage 1 baseline, the feature tables, the Stage 2 fits and
  scoring, and the report tables and figures — deterministically
  reproduces the reported numerical results and artefacts from committed
  (or restored) frozen inputs using the commands below. Where byte-level
  identity is additionally pinned by a test, the step says so.

No API key is needed for any reproduction step below. Keys (SerpAPI,
Anthropic) were only needed to create the frozen snapshots.

## 2. Environment

Python 3.14 (developed on 3.14.6; the report-side CI also runs 3.14).

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt                                  # main pipeline
pip install -r surrey-election-extractor/requirements.txt        # Layer 1A subproject
pip install -r surrey-election-no-news-baseline/requirements.txt # Stage 1 subproject
```

For an environment pinned to the exact package versions the verified
end-to-end rebuild ran under, install the committed lockfile instead:

```bash
pip install -r requirements.lock.txt
```

Building the PDF also requires the system command `latexmk` and a TeX
distribution such as MacTeX or TeX Live. These are system dependencies, not
Python packages, and are not installed by either requirements file.

## 4. Rebuild order (fresh clone)

Run everything from the repository root with the `.venv` active. Steps 1, 2,
the primary-freeze verification in Step 4, Step 5 and Step 6 need only
committed files after the Stage 1 bundle has been rebuilt or restored. The
optional feature-table rebuilds in Step 3 and tests that report themselves as
skipped additionally need the relevant git-ignored LLM tranches restored; the
Step 4 case-study scoring commands then consume those tables plus the Stage 1
bundle. Restore instructions and the OneDrive link are in the root README's
**Large local artefacts** table. Because the feature tables and case-study
results are committed, an examiner can skip those optional rebuilds and still
verify every reported result.

**Step 1 — Layer 1A: election releases (offline, deterministic).**

```bash
PYTHONPATH=surrey-election-extractor .venv/bin/python surrey-election-extractor/scripts/generate_master_election_database.py
PYTHONPATH=surrey-election-extractor .venv/bin/python surrey-election-extractor/scripts/generate_final_position_qa.py
PYTHONPATH=surrey-election-extractor .venv/bin/python surrey-election-extractor/scripts/generate_final_election_data_release_audit.py
PYTHONPATH=surrey-election-extractor .venv/bin/python surrey-election-extractor/scripts/generate_no_news_electoral_baseline.py
PYTHONPATH=surrey-election-extractor .venv/bin/python surrey-election-extractor/scripts/generate_no_news_candidate_contests.py
```

**Step 2 — Stage 1: the history-only baseline.** Emit the split manifest and
leakage audit first (the bundle builder copies them in when present and
warns otherwise), then train:

```bash
PYTHONPATH=surrey-election-no-news-baseline .venv/bin/python \
  surrey-election-no-news-baseline/scripts/build_candidate_split_and_leakage.py
PYTHONPATH=surrey-election-no-news-baseline .venv/bin/python -m no_news_baseline.cli train
```

Acceptance: the run logs out-of-fold MAE 9.85 and holdout MAE 4.53, and
writes `surrey-election-no-news-baseline/outputs/model_bundle_v1/` with its
SHA-256 manifest.

**Step 3 — Layer 4: the news feature tables (optional).** The committed
`news_features/news_feature_table_v1/v2/v3exp/v3party.csv` are frozen
releases. With the relevant LLM tranches restored, rebuild them and the two
final-report case-study tables with:

```bash
.venv/bin/python -m src.news_features.build_feature_table
.venv/bin/python -m src.news_features.build_feature_table_v2
.venv/bin/python -m src.news_features.build_feature_table_v3exp
.venv/bin/python -m src.news_features.build_feature_table_v3party
.venv/bin/python -m src.news_features.build_haslemere_probe_features
.venv/bin/python -m src.news_features.build_woking_south_blind_features
```

The v1 and v2 production tables are pinned byte-for-byte by
`tests/test_feature_table_rebuild.py`. The v3exp, v3party, Haslemere and
Woking South extensions are rebuilt from the corpus manifest named in their
own metadata and checked by their dedicated release/contract tests; the
byte-identical test does not claim to cover those four extensions.

**Step 4 — Stage 2: verify the historical freeze, then rebuild allowed
case-study outputs.**

The following three commands document the historical one-time sequence that
created the final v1/v2 evidence. They are **not routine verification
commands**. When the local prediction CSV already exists, each freeze runner
refuses to overwrite it. On a bare clone the CSV is deliberately absent, so a
freeze runner can reconstruct the missing local bytes and will rewrite its
protocol/manifest; do that only in an isolated reproduction checkout and
inspect the resulting Git diff. The unblinding runner refuses while the
committed unblinding result directory exists.

```bash
PYTHONPATH=src .venv/bin/python -m news_modelling.run_blinded_2026_predictions
PYTHONPATH=src .venv/bin/python -m news_modelling.run_blinded_2026_predictions_v2
PYTHONPATH=src .venv/bin/python -m news_modelling.unblind_2026
```

For current reproduction, verify that historical sequence instead:

```bash
.venv/bin/python -m audit_leakage_provenance
```

The audit checks the Stage 1 bundle inputs, absence of outcome columns in the
Stage 2 matrices, the committed freeze manifests, the one-time unblinding
record and Git chronology. If the git-ignored v1/v2 prediction CSVs are
present, it also verifies their current bytes; without them it performs the
committed manifest/unblinding verification and labels the files
`manifest_only`. Exact rescoring of the historical unblinding requires both
local files restored at
`news_features/blinded_2026_predictions_v1/blinded_predictions.csv` and
`news_features/blinded_2026_predictions_v2/blinded_predictions.csv`. Because
they are not committed, exact rescoring is not claimed as a bare-clone
guarantee; the manifest/Git verification is.
Deleting frozen directories and generating new predictions can test code in
an isolated copy, but cannot replace the historical chronology evidence.

The final-report case studies have separate roles. Haslemere is explicitly
post-unblinding and may be regenerated. Woking South reuses its committed
pre-contact protocol; the prediction runner must reproduce the committed
prediction bytes before the git-locked unseal will read the outcome:

```bash
PYTHONPATH=src .venv/bin/python -m news_modelling.haslemere_probe_prediction
PYTHONPATH=src .venv/bin/python -m news_modelling.woking_south_blind_predict
PYTHONPATH=src .venv/bin/python -m news_modelling.woking_south_unseal
```

The Woking South historical order was `woking_south_blind_protocol` → news
collection/extraction → feature table → `woking_south_blind_predict` → commit
prediction bytes → `woking_south_unseal`. Re-running the protocol now is not
evidence of pre-contact registration; its committed Git history is.

Every post-unblinding diagnostic regenerates its `news_features/<name>_v1/`
evidence directory via its module in `src/news_modelling/` (one module per
analysis; see that README's file guide).

**Step 5 — Layer 7: the report tables and figures.** Generate the 23-table
machine-readable pack, all report-used LaTeX projections, the complete
ten-figure analysis pack and the separately stored pipeline overview. Then copy
the report-facing images into `report/figures/`:

```bash
PYTHONPATH=src .venv/bin/python -m news_modelling.build_report_tables
PYTHONPATH=src .venv/bin/python -m news_modelling.report_appendix_tables
PYTHONPATH=src .venv/bin/python -m news_modelling.make_report_figures
PYTHONPATH=src .venv/bin/python -m news_modelling.study_design_figure
PYTHONPATH=src .venv/bin/python -m news_modelling.corpus_funnel_figure
PYTHONPATH=src .venv/bin/python -m news_modelling.pipeline_overview_figure
PYTHONPATH=src .venv/bin/python -m news_modelling.framework_figure
PYTHONPATH=src .venv/bin/python -m news_modelling.reform_party_split_figure
cp outputs/report_figures_v1/fig0_study_design.png report/figures/
cp news_features/pipeline_overview_v1/pipeline_overview.png report/figures/
cp outputs/report_figures_v1/fig0c_framework.png report/figures/
cp outputs/report_figures_v1/fig1_confirmatory_deltas.png report/figures/
cp outputs/report_figures_v1/fig2_seat_totals.png report/figures/
```

Build-time assertions fail if any number drifts from its frozen source;
`outputs/report_tables_v1/manifest.json` pins the SHA-256 of every table-pack
input. `tests/test_report_appendix_extension_tables.py` rebuilds all 14 LaTeX
tables included by the report and compares their bytes with the committed
outputs. `reform_party_split_figure.py` writes Figure 5 to both the analysis
pack and `report/figures/` itself, so it needs no copy command.

**Step 6 — the report PDF.**

```bash
make -C report
```

`report/report.tex` reads generated LaTeX tables from
`outputs/report_tables_v1/latex/`, images from `report/figures/`, and the
committed `report/references.bib` and template files. The report-facing image
copies are committed, so `make` also works without regenerating figures. The
Makefile tracks the generated LaTeX directory and figure copies as dependencies;
`make -C report force` performs an unconditional rebuild. No duplicate `a*.tex`
tables are kept under `report/`.

## 8. Verification without rebuilding anything

```bash
.venv/bin/python -m audit_leakage_provenance   # six offline checks: query/corpus chronology, Stage 1
                                               # split + leakage, Stage 2 isolation/freeze, area selection
.venv/bin/python -m pytest tests -q                                                # root news side
( cd surrey-election-no-news-baseline && PYTHONPATH=. ../.venv/bin/python -m pytest tests -q )  # Stage 1
( cd surrey-election-extractor && ../.venv/bin/python -m pytest tests -q )          # extractor
.venv/bin/python -m pytest demo/test_viva_pack.py -q                               # viva pack
```

The first command writes the detailed verdict to
`outputs/leakage_provenance_audit_v1.json` and the compact event ledger to
`outputs/provenance_audit_v1.csv`. Dates not evidenced by the repository stay
blank in the CSV rather than being inferred from polling day or Git history.

Tests that need git-ignored local inputs (the frozen LLM tranches, the
collection runner state) skip themselves on a fresh clone; each skip message
names the file to restore or the builder that recreates it.

## 9. Outputs

Rebuilt products land where the committed or local versions live: extractor
releases under `surrey-election-extractor/outputs/`, the git-ignored Stage 1
bundle under `surrey-election-no-news-baseline/outputs/model_bundle_v1/`,
feature tables and compact experiment evidence under `news_features/`, report
packs under `outputs/report_tables_v1/` and `outputs/report_figures_v1/`, and
the image copies consumed by LaTeX under `report/figures/`. Git contains the
report-facing packs, compact frozen feature releases and audit evidence.
Bulky raw text, model responses, workbooks, model binaries and frozen blinded
prediction CSVs remain local/OneDrive and are either regenerated or verified
against committed hashes as described above.
